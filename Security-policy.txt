1. The Single-Tenant Illusion (Operational Mandate)

The AI agent must enforce an absolute data isolation boundary across all database interactions. Every client instance operating on this infrastructure must interact with the application as if they are the sole occupant of the server and database cluster.
Any code snippet, raw query, or ORM method generated by the AI that accesses records without validating a tenant_id context will fail security review.

2. Strict Input & Variable Sanitation Matrix

To protect our isolated database systems from cross-tenant data leaks and common web vulnerabilities, all input processing layers must follow these strict validation rules:

A. SQL Injection Prevention

• Parameterized Queries Only: The AI agent must strictly write SQL queries using standard placeholder formats (e.g., $1, $2).
• Ban String Concatenation: Do not construct database queries by mixing variables directly into strings (e.g., WHERE tenant_id = ' + req.tenant.id + ').

B. Route-Level Input Sanitation

• Request Body Validation: Every single POST, PUT, and PATCH request must be structurally validated using a schema tool (such as Zod or Joi) before hitting the controller logic.
• UUID Verification: Any parameter containing a unique identifier (such as id, project_id, or client_id) must pass explicit UUIDv4 regex checks. If a parameter fails validation, the system must immediately block execution and throw a 400 Bad Request exception.

3. The Secure Multi-Tenant Architecture Framework


Context-Bound Scope Enforcement Pattern

The AI agent must construct all data query operations to mirror this secure structural design pattern, matching user identity parameters with verified host context values:
typescript
// repositories/project.repository.ts
import { Pool } from 'pg';
import { ProjectRecord } from '../models/project.interface';

export class ProjectRepository {
    private db: Pool;
    constructor(dbPool: Pool) { this.db = dbPool; }

    /**
     * Retrieves an isolated single project record.
     * Enforces data isolation by requiring both the project ID and verified tenant ID context.
     */
    async findProjectById(projectId: string, tenantId: string): Promise<ProjectRecord | null> {
        const sqlQuery = `
            SELECT id, tenant_id, client_id, project_name, status, current_phase, progress_percentage, estimated_cost 
            FROM projects 
            WHERE id = $1 AND tenant_id = $2 
            LIMIT 1;
        `;
        
        // Context variables are securely passed into the parameterized execution array
        const result = await this.db.query(sqlQuery, [projectId, tenantId]);
        
        if (result.rows.length === 0) return null;
        return result.rows[0] as ProjectRecord;
    }
}

4. Role-Based Access Control (RBAC) Cleardowns

Authentication alone does not grant access. The AI agent must block route access using this strict Role-Based Access Matrix:

Role Cleardown	Allowed Domain Operations & API Methods
admin	Full Authority: Can invoke all GET, POST, PUT, DELETE methods across user profiles, projects, structural cost matrices, and change order lists within their tenant scope.
field_staff	Field Maintenance Clearings: Can execute GET commands across active tenant data profiles. Can invoke PUT updates exclusively on projects.current_phase and projects.progress_percentage. Blocked from creating or deleting records.
client	Portal Space Bounds: Access is structurally limited to records directly bound to their profile identity (WHERE client_id = req.user.id). Can invoke PUT updates only on change order records requiring their direct legal approval signature.


5. Security Failure & Audit Protocols

• Context Discrepancy Abort: If the tenant_id contained inside a user's authenticated session token does not match the active req.tenant.id resolved by the domain middleware, the system must treat the event as an unauthorized intrusion attempt.
• Standard Failure Response: When blocking an execution thread due to an access mismatch, the API must drop the connection using a generic 403 Forbidden status payload. Do not return structural path diagnostics or detailed schema hints to unverified endpoints.
